Summary of All Relationships

Key points for viva:
  • There are NO many-to-many relationships in this schema — no junction/bridge tables needed.
  • All relationships are One-to-Many (1:M).
  • TransactionHistory has two FK references to the same table (Accounts) — one for sender, one for receiver.
  • AuditLog has no FK constraints by design — audit records must survive even if referenced entities are deleted.
  • ON DELETE CASCADE ensures child records are auto-deleted when parent is removed.
  • ON DELETE SET NULL preserves the transaction record but nullifies the reference when an account is deleted.
